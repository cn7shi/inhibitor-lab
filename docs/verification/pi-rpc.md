# Pi RPC 中止验证（2026-10-05）

基线 `e89064b`；本阶段实现显式启用的合作式中止，保持文本和 Pi JSON 观察模式的默认行为。开发、故障、决策分别记录在阶段 2、D008 和 D009。

## 验收与实现

一次运行发送一个提示。首次规则触发后依次发送 `clear_queue` → `abort` → `get_state`；所有命令关联唯一 ID。成功响应和空闲状态获得后关闭 stdin，等待 Pi 退出。重复规则可以各自记录，但不会重复启动控制流程。

只有协议确认、完整采集、完整适配和 Pi 正常退出同时成立，最终才记为 `aborted`，启动器返回 3。自然完成返回 0；异常返回 2。原始子进程退出码独立保存。

读取、写入分线程，stdin 写入不会阻塞主循环的期限检查。期限采用单调时钟，默认总运行 30 秒、中止流程 / 关闭收尾各 5 秒。异常路径尝试结束直接子进程，停止等待可能由后代持有的输出管道，并明确标记 `capture_complete: false`；不宣称已处理整个进程树。

### 真实对照条件

- Pi 固定为 `1.0.3`；通过 Scoop 管理的 Node `24.20.0`；CI 固定相同 Node 版本。
- 模型由 `127.0.0.1` 的确定性服务提供，不访问外部模型，不需要密钥。只启用真实 `read` 工具，使用独立配置与实验目录，关闭扩展、自动重试和压缩。
- 两种 RPC 模式在第三次工具前使用相同的一秒回复延迟。仅记录场景仍完成第三次读取，作为有效对照；中止场景在此窗口内停止。
- 这验证中止协议链路，不证明任意时序下都能阻止下一次调用。模拟进程另在收到清队列请求时故意启动工具，验证 `tool_started_after_trigger` 如实记录这个竞态。

## 遇到的真实失败与处理

1. 首次格式检查发现新测试函数声明遗漏 `fn`，修正后格式和编译通过。
2. Node 24.17.0 下，Pi 在中止成功、状态空闲、stdin 关闭之后出现 `UV_HANDLE_CLOSING`，两次都以 `-1073740791` 退出。证据：`runs/pi-rpc-abort-bL8ytq/`、`runs/pi-rpc-abort-p0Dvb6/`。启动器均返回 2，最终控制结果均为失败。
3. 查证 [Node 24.20.0 发布记录](https://nodejs.org/en/blog/release/v24.20.0) 中的 [Windows 退出修复 #61999](https://github.com/nodejs/node/pull/61999)，通过 `scoop install nodejs-lts@24.20.0 --no-update-scoop` 安装并校验官方哈希；旧 24.17.0 仍保留，npm 全局前缀仍为原来的 `D:\DevEnvironment\npm-global`。
4. 升级后同一 RPC 对照通过，没有修改 Pi 依赖代码或靠睡眠掩盖退出错误。该结果支持运行时缺陷判断；没有独立调试 Node 的原生崩溃栈，因此不声称完成底层根因证明。
5. 自查补齐了协议确认后退出失败的显式 `control_failed` 记录，并为这种情况增加回归测试。RPC 仅记录模式也记录触发之后的新工具调用，便于与中止模式比较。

## OCR 委托规则复核

实际运行 `ocr delegate preview` 和 `ocr delegate rule`（`OCR_NO_UPDATE=1`），复核 7 个代码 / 配置文件、4 组规则：

- Rust：`src/main.rs`、`src/control.rs`、`src/bin/mock-agent.rs`、`tests/control.rs`。核查输入校验、ID 关联、关闭条件、线程生命周期、期限和非零退出；未留下已确认而未修复的问题。异常路径不等待读取线程是保持控制期限的明确取舍，见 D008。
- JavaScript：`integrations/pi/check-local.mjs`。核查两组实验输入一致性、响应取消后的定时器、输出错误处理与断言。复用已有 `captureOutput`，只在本机提供固定回复。
- 包配置：`integrations/pi/package.json`。只新增验证脚本，没有新增依赖或使用浮动依赖。
- CI：`.github/workflows/check.yml`。固定 Node 修复版本，加入 RPC 对照；设置 10 分钟任务期限，维持只读权限，不忽略验证失败。

原始规则在 `runs/pi-rpc-review-2026-10-05/ocr-rules.json`。由当前助手按规则执行，不是第二个独立模型复审。Markdown 另核对事实；CI 最终状态随提交保存在 [GitHub Actions](https://github.com/cn7shi/inhibitor-lab/actions)，此处不预填尚未执行的远程结果。
