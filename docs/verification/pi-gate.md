# Pi 执行前准入验证

日期：2026-10-05。变更基线：`c8decbc`。本报告记录本地实测，远端 [Check 工作流](https://github.com/cn7shi/inhibitor-lab/actions) 随提交运行。

后续阶段已补充[并发批次与两层嵌套验证](pi-boundaries.md)。下文“尚未验证”描述本报告当时的首轮范围。

## 结论

真实 Pi 1.0.3 使用本机确定性模型服务，两次读取失败后尝试写入测试文件。相同回复、没有额外延迟的两组对照中，仅记录组写入成功，拦截组文件不存在。Rust 的拒绝决定与扩展应用确认对应，Pi 正常退出，未通过强制终止伪装拦截成功。

这验证了合作式执行前准入链路；真实模型行为、并发及嵌套调用专项尚未验证。当前只保证关闭后不批准新请求，无法撤销之前已批准的调用。

## 接口与证据

- `--format pi-rpc --tool-gate --on-trigger record|block`，Pi 显式加载 `integrations/pi/tool-gate.js`。
- Rust 先查询扩展版本标记，缺失或不兼容时不发送业务提示。这个标记是合作协议检查，不是防替换的身份认证。
- 扩展的 `tool_call` 钩子等待自有 RPC 确认，最长 5 秒。只有明确布尔 `true` 且没有拒绝锁定或取消时放行；异常与超时默认拒绝。
- Rust 按请求 ID、工具调用 ID 和名称关联决定；扩展通知实际采用结果，未确认或不匹配不能报告成功。其它扩展的交互请求不会被自动批准。
- 规则首次触发关闭本次运行准入。拒绝产生的合成 `tool_execution_end` 单独记录为 `tool_blocked_result`，不作为真实工具失败继续计数。
- `gate_closed` 是关闭事实；`gate_decision` 是决定；`gate_applied` 是扩展采用结果；最终还要检查子进程退出与采集完整性。`blocked_tool_count` 统计确认应用拒绝的调用，不等同于进程树被终止。

Pi 的 `tool_execution_start` 在执行前钩子之前发出，因此即使拒绝成功，也会出现 `tool_started_after_trigger`。本次以实际文件效果补充验证，不把该事件当作执行证据。

## 适用边界与后续

1. Pi 可以先准备同批全部工具，再执行已批准工具。准入关闭不能收回既有批准，也无法撤销工具已产生的效果；首轮测试每次模型回复只有一个工具调用。
2. 扩展返回 `block: true, terminate: true`；Pi 对整批的结束有自己的条件，本实验只验证单工具批次。超出期限仍按失败收尾，不承诺任何工作负载都会正常结束。
3. 信任本地 Pi 与扩展，同权限恶意代码、扩展自行产生的副作用以及工具派生进程不属于此门禁隔离范围。
4. 不自动恢复；目前只能开始新运行重置。人工恢复、跨运行状态、本地日志跟随和 MCP 代理留待后续。
5. 沿用 64 KiB 行上限、每次运行随调用数增长的关联状态和同步日志写入；不是无限负载或硬实时方案。
6. Pi 在未知工具或参数校验失败时可能不调用准入钩子；当前将没有对应决定的错误结果保守按协议失败结束运行，不从错误文本推断是否执行。该限制来自本地 `prepareToolCall` 源码复核，故障模拟覆盖成功与失败两种未准入结果；尚未用真实模型触发参数错误。

复现：构建启动器并安装锁定的 Pi 依赖后，执行 `npm --prefix integrations/pi run check:gate`。该脚本核对预期的启动器退出码 3，因此验收通过时自身返回 0；Windows CI 已加入相同对照。
