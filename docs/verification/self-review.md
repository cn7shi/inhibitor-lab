## R1 · P2 · 损坏 UTF-8 可成为规则证据（已修复）

- 条件：Pi stdout 的工具结果包含无效 UTF-8 字节，例如 `toolCallId` 内的 `0xff`。
- 原因：采集器使用替换解码，但没有传递解码损坏信息；适配器看到的是替换后的有效 JSON。
- 影响：本不完整的工具结果可能参与失败计数，启动器仍返回 0 并标记适配完整。
- 复现：新增 `pi-invalid-utf8` 子进程场景。修复前测试失败，实际返回 0，预期 2。
- 修复：输出增加 `invalid_utf8`；Pi stdout 的损坏行不参与规则，记录 `adapter_error` 并标记不完整，最终返回 2；后续有效事件继续处理。
- 验证：新增进程回归测试通过；合法 U+FFFD 和 U+2028 的测试通过，避免仅凭替代字符误判损坏。

## R2 · P2 · 半条日志会使本地实验跳过 Pi 清理（已修复）

- 条件：本地实验触发超时，日志第一条启动记录已完整，但最后一条记录尚未写完。
- 原因：超时回调先解析整份 JSONL；末行解析失败后进入忽略异常分支，未取到 Pi PID，只关闭启动器。
- 影响：可能残留 Pi；在后代仍持有管道时，实验结束也可能继续等待。
- 复现：提取原 PID 查找逻辑并喂入完整启动记录加半条尾记录；解析测试和真实进程清理测试均失败。测试自身的 finally 会结束其创建的进程。
- 修复：只读取日志开头最多 64 KiB，解析第一条已换行的启动记录并验证 PID；清理异常不再静默丢弃。
- 验证：3 项 Node 测试通过，覆盖半条尾记录、无效 PID / 不完整启动记录及真实测试进程退出。
- 边界：这是本地实验程序的直接进程清理，不是任意后代进程树的可靠终止方案；缺失启动记录时无法确认 Pi 清理，仍需在后续生命周期设计中处理。
